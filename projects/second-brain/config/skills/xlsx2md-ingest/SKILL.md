# xlsx2md-ingest (XLSX → Clippings MD)

## 언제 사용하는가

- 사용자가 "이 엑셀 잉게스트해줘" / "xlsx를 vault에 넣어줘"라고 요청할 때
- 스프레드시트 내용을 wiki 지식으로 만들고 싶은데 원본이 md가 아닐 때

이 스킬은 **변환과 Clippings 투입까지만** 담당한다. 개념 추출·wiki 생성·커밋·PR은
하지 않는다 (기존 vault-ingest / vault-ingest-claude 몫). PDF는 `pdf2md-ingest`,
HWP/HWPX는 `hwp2md-ingest`를 쓴다.

.xls(구 바이너리)·.csv는 이 스킬의 범위가 아니다. .xls는 사용자에게 .xlsx로 다시
저장하도록 안내하고, .csv는 이미 텍스트이므로 직접 md 표로 옮긴다.

## 전제 도구 (없으면 안내 후 중단 — 자동 설치 금지)

| 도구 | 확인 | 설치 안내 |
|---|---|---|
| uv (X1/X2 — openpyxl 자동 준비) | `command -v uv` | `brew install uv` |
| unzip (차트·피벗 탐지) | `command -v unzip` | macOS·리눅스 기본 포함 |
| pandas (선택 — 대용량 시트 통계 보강) | `python3 -c "import pandas"` | 필요할 때만. 없어도 X2는 동작한다 |

Excel·LibreOffice는 필요 없다. openpyxl은 PEP 723 메타데이터로 uv가 실행 시점에
준비한다 (전역 설치 불필요).

**스킬 발견용 설치** (머신별 1회): `$VAULT_DIR/.claude/skills/`에 심링크

```bash
mkdir -p "$VAULT_DIR/.claude/skills"
ln -s "$VAULT_DIR/projects/second-brain/config/skills/xlsx2md-ingest" \
      "$VAULT_DIR/.claude/skills/xlsx2md-ingest"
```

## 절차

### 0. 게이트 (변환 전 — 하나라도 실패하면 아무것도 쓰지 않고 보고)

1. **커밋 가능성**: 사용자에게 확인 — "이 엑셀은 팀 공유 vault에 커밋 가능한 문서인가?"
   **엑셀은 PDF·HWP보다 개인정보를 담을 확률이 훨씬 높다.** 인사·급여·명부·정산 파일이
   전형적이고, 한 행이 곧 한 사람인 구조라 시트 하나가 그대로 개인정보 대장이 된다.
   변환 전에 아래를 눈으로 확인한다:
   - 주민등록번호·생년월일·연락처·이메일·주소·계좌번호 열
   - 개인별 급여·평가·징계 명세 (집계표는 괜찮아도 개인별 행은 아니다)
   - **숨은 시트·필터로 감춰진 행** — 화면에 안 보여도 스크립트는 전부 읽는다.
     X1 산출의 `<!-- sheet: ... 숨김 시트 -->` 주석으로 확인한다.

   하나라도 해당하면 정식 잉게스트(§3 산출·마무리)는 중단한다. 변환 자체가 필요한
   경우에는 § vault 밖 변환 모드를 제안하고, 사용자가 그 모드를 명시적으로 선택한
   경우에만 진행한다. "개인정보 열만 지우고 커밋"은 이 게이트의 통과 사유가 아니다 —
   원본 xlsx가 `raw/`에 그대로 들어가므로 열 삭제는 md에만 적용되고 원본은 남는다.
2. **VAULT_DIR resolve**: 사용자 명시값 > vault 구조(`VAULT_RULES.md`, `wiki/`, `raw/`,
   `Clippings/`, `templates/`)가 확인된 현재 루트 > 그 외에는 사용자에게 질문.
   `~/knowledge` 조용한 fallback 금지. 절대경로로 resolve.
3. **중복**: `raw/xlsx/<원본파일명>.xlsx`가 이미 있으면 중단·보고 (raw/는 append-only).
   파일명은 `docs/raw-layout.md` § 파일명 정규화를 적용한 뒤 비교한다.

### 1. 구조 측정 → 전략 제안

X1 스크립트는 읽기 전용·저비용이므로 먼저 돌려서 그 통계로 전략을 판정한다:

```bash
SKILL_DIR="$VAULT_DIR/projects/second-brain/config/skills/xlsx2md-ingest"
uv run "$SKILL_DIR/scripts/x1-convert.py" <file.xlsx> > <scratch>/converted.md
unzip -l <file.xlsx> | grep -E 'xl/(charts|drawings)/|pivot' || echo "차트·피벗 없음"
```

`x1-convert.py`는 md를 stdout으로, 통계를 stderr 마지막 줄로 낸다:

```
stats sheets=<시트 수> rows=<데이터 행 합계> merged=<병합 범위 수> formulas=<수식 셀 수> truncated=<bool>
```

시트별 크기·병합·수식·숨김 여부는 산출 md의 `<!-- sheet: <이름> — N행 × M열, ... -->`
주석에 들어 있다. 이 주석과 위 zip 탐지 결과로 **시트마다** 전략을 정한다:

| 시트 프로파일 | 채택 전략 | 비고 |
|---|---|---|
| 데이터 행 ≤ 1000, 헤더 1행, 병합 없음(또는 상단 제목행뿐) | **X1** — 스크립트 산출 그대로 | 무료·초 단위. 표 형태가 깨끗한 기본 경로 |
| 데이터 행 > 1000 | **X2** — 스키마 + 요약통계 + 샘플 행 | `--max-rows 1000`. 전량 전사는 md만 비대해지고 wiki 가치가 없다 |
| 병합이 헤더 영역에 걸쳐 헤더가 2행 이상 / 산출 헤더가 `col2`·`col3`로 채워짐 | **X3** — Claude가 직접 판독·재구성 | 비용 고지 후 사용자 확인 |
| 차트·피벗이 데이터의 본체 (셀 값은 뼈대만) | **X3** | 차트 내용은 셀에 없다. 재구성 불가하면 사용자에게 원본 확인 요청 |
| 값 있는 셀 0 | 건너뜀 | md에 `_(빈 시트)_`만 남긴다 |

측정 결과(시트 수·시트별 행×열·병합·수식·차트/피벗 유무)와 시트별 제안·예상 비용을
사용자에게 보여주고 **확인받은 뒤** 변환한다. 1000행 경계는 실측이 아닌 초기 추정치이므로
(§ 근거·주의), 경계 근처(700~1500행)면 두 선택지를 함께 제시한다.

### 2. 변환 (산출은 스크래치 디렉토리에 — 완성 전 vault에 쓰지 않는다)

- **X1**: `uv run "$SKILL_DIR/scripts/x1-convert.py" <xlsx> > <scratch>/converted.md`
- **X2**: 같은 스크립트에 `--max-rows 1000`(경계는 §1에서 확정한 값). 초과 시트만
  스키마·요약통계·샘플 행으로 대체되고, 나머지 시트는 X1 그대로 전사된다.
  샘플 행 수는 `--sample N`(기본 5).
- **X3** (클코 자신이 수행): X1 산출과 필요하면 원본 셀 덤프를 직접 읽고 표를
  재구성한다. 규칙:
  - 보이는 값만 충실히 옮긴다 — 추측·보완·요약 금지 (환각 방지)
  - 다층 헤더는 `상위-하위` 결합 단일 헤더로 편다 (예: `2025 상반기`)
  - 병합으로 세로로 이어지는 분류 열은 각 행에 값을 반복해 채운다
  - 차트는 축·계열·라벨을 텍스트로 서술하고, 원본 수치가 셀에 없으면 그 사실을 명시
  - 시작 전 예상 비용을 고지한다 — 시트 덤프를 그대로 정독하므로 토큰 비용이 시트
    크기(행×열·문자수)에 비례한다. 대형 시트는 X2로 범위를 좁힌 뒤 X3을 얹는다

공통 규칙:

- **수식은 계산된 값을 쓴다.** 파일에 캐시된 계산 결과가 있으면 그 값이 들어가고,
  캐시가 없으면(Excel이 한 번도 저장하지 않은 파일) 수식 문자열로 대체되며 stderr에
  경고가 뜬다. 이 경고는 완료 보고에 반드시 옮긴다. 산식 자체가 지식인 문서(모델·정산
  로직)는 `--formulas`로 `123 (=SUM(B4:B6))`처럼 값과 수식을 병기한다.
- 시트마다 `## <시트명>` H2로 구분한다. 시트명은 그대로 쓴다.
- 빈 시트는 건너뛰지 않고 `## <시트명>` + `_(빈 시트 — 값 있는 셀 없음)_`로 남긴다.
  시트 수가 md와 원본에서 일치해야 §4 검증이 성립한다.
- 전부 빈 행·열은 제거한다 (표 사이 간격 열이 md 표를 깨뜨리는 것을 막는다).
- 숫자 서식은 보존한다 — 통화 기호(`₩125,000,000`), 백분율(`62.0%`), 천단위 구분,
  날짜 ISO(`2026-01-01`). 서식 없는 raw 숫자로 떨어뜨리지 않는다.
- 병합셀은 좌상단 값만 채우고 나머지 칸은 빈칸으로 둔다 (X3에서 재구성 대상).

### 3. 산출·마무리

1. 원본 보존: `cp <xlsx> "$VAULT_DIR/raw/xlsx/<원본파일명>.xlsx"` (디렉토리 없으면 생성.
   .xlsm은 확장자 그대로 유지)
2. frontmatter를 붙여 `Clippings/<원본파일명 확장자만 .md>`로 이동:

   ```yaml
   ---
   source_xlsx: "raw/xlsx/<원본파일명>.xlsx"
   source_sha256: "<shasum -a 256 결과>"
   converted_by: X1|X2|X3
   converted_at: "YYYY-MM-DD"
   sheets: N
   rows: N          # 전 시트 데이터 행 합계
   truncated: true|false   # X2로 요약만 담은 경우 true
   ---
   ```

   본문 첫 줄은 원제목 H1 (`# <문서 제목>`). 시트마다 전략이 다르면 `converted_by`에는
   개입이 가장 큰 전략 하나를 적고(X3 > X2 > X1), 시트별 전략은 본문 시트 주석에 남긴다.
3. 완료 보고: 전략·시트 수·행 합계·`truncated` 여부·MD 크기·경로 + 수식 캐시 경고(있으면)
   + "잉게스트는 vault-ingest(-claude)로 별도 실행" 안내.

### 4. 검증 (완료 선언 전)

- frontmatter 필수 키 7종 존재 (`source_xlsx`·`source_sha256`·`converted_by`·
  `converted_at`·`sheets`·`rows`·`truncated`)
- `sheets:` 값 = 원본 시트 수 = stderr `stats sheets=` = md의 `## ` H2 개수 (빈 시트 포함).
  하나라도 어긋나면 실패 처리
- `rows:` 값 = stderr `stats rows=`
- `truncated: true`인데 요약 통계 절(`### 스키마·요약 통계`)이 하나도 없으면 실패 처리.
  반대로 `truncated: false`인데 X2로 처리한 시트가 있으면 값 불일치 — 실패 처리
- MD 0바이트, 또는 값 있는 셀이 전 시트에서 0이면 실패 처리
- 수식 캐시 경고가 있었는데 보고에 빠졌으면 완료 선언 금지 (독자가 수식 문자열을
  계산 결과로 오독한다)
- 모든 산출 경로가 `$VAULT_DIR` 아래인지 (vault 밖 변환 모드에서는 반대 — 아래 § 참고)

## vault 밖 변환 모드 (커밋 불가 문서용)

게이트 1(커밋 가능성) 실패 — 인사·급여·명부·고객사 파일 — 인데 변환 산출물 자체는 필요한
경우의 공식 경로. 게이트가 이 모드를 **제안**할 수는 있지만, 진입은 사용자의 명시적
선택으로만 한다 (기본값 아님). **엑셀은 개인정보 밀도가 높은 포맷이라 pdf2md·hwp2md보다
이 모드로 갈 일이 상대적으로 많다** — 정식 잉게스트를 기본으로 두고 예외를 다루는 게
아니라, 매번 게이트 1을 실질적으로 심사한다는 뜻이다.

정식 절차와의 차이:

| 단계 | 정식 잉게스트 | vault 밖 변환 모드 |
|---|---|---|
| §0 게이트 2·3 (VAULT_DIR·중복) | 수행 | 중복 검사 생략 (raw/에 아무것도 안 들어가므로) |
| §1 구조 측정·전략 제안 | 동일 | 동일 |
| §2 변환 | 동일 | 동일 |
| §3 산출·마무리 | raw/xlsx/ 보존 + Clippings/ 투입 | **전부 생략** — vault 아래에 아무것도 쓰지 않는다 |
| §4 검증 | 산출 경로가 `$VAULT_DIR` 아래 | 산출 경로가 `$VAULT_DIR` **밖** (스크래치 또는 사용자 지정 경로) |

추가 규칙:

- 산출 MD는 세션 스크래치 디렉토리 또는 사용자가 지정한 vault 밖 경로에만 둔다.
  frontmatter 부착은 선택이며, 붙이더라도 vault 밖 산출물에만 붙인다.
- 산출 MD는 파생 작업(집계·대조·요약 등)의 **입력**으로만 쓴다. 파생 결과물이 vault로
  들어갈 때는 커밋 전에 개인정보(성명·연락처·이메일·주민번호·계좌·사업자번호·상세 주소)
  미유입을 diff 기준으로 검증한다 (`VAULT_RULES.md` § Core Rules의 개인 데이터 금지 조항).
  개인별 행은 집계 수치(합계·평균·분포)로만 vault에 들어갈 수 있다.
- 완료 보고에 모드 명칭("vault 밖 변환")과 산출 경로를 명시해, 정식 잉게스트로
  오인되지 않게 한다.

## 에러 처리 (fail-closed)

- 도구 부재(uv·unzip) → 위 설치 안내 후 중단. 자동 설치 금지.
- 암호 걸린 통합 문서 → openpyxl이 열지 못한다. 암호 해제 후 재시도 안내하고 중단.
- .xls·.csv 등 범위 밖 확장자 → 스크립트가 exit 1. 위 § 언제 사용하는가의 안내로 중단.
- 변환 실패 → 스크래치만 정리하고 `Clippings/`·`raw/`는 건드리지 않는다.
- 게이트 실패 → 아무것도 쓰지 않고 사유 보고.
- 검증(§4) 실패 → 이미 `Clippings/`에 옮긴 파일이 있으면 그것만 회수하고, `raw/`에
  복사한 원본은 손대지 않는다 (append-only). 회수 사실을 보고에 명시한다.

  이 스킬에는 아직 없다. 산출 md 크기와 wiki 유용성의 실사용 관찰로 조정 대상.
- 검증된 것은 스크립트 동작뿐이다: 2026-08-26 합성 통합 문서(4시트 — 통화·백분율 서식,
  병합 헤더, 빈 열·빈 시트, 다층 헤더, 1200행 시트)로 X1 전량 전사·X2 요약·병합 처리·
  숫자 서식 보존·파이프 이스케이프·숨김 시트 표시·수식 캐시 없음 경고를 스모크 확인.
- openpyxl은 셀에 **캐시된** 계산 결과만 읽는다. 수식을 재계산하지 못하므로, 값이
  비어 있으면 수식 문자열이 대신 들어간다 (§2 공통 규칙).
- 차트·피벗의 내용은 셀에 없다. `unzip -l`로 존재만 탐지할 수 있고, 판독은 X3이 맡되
  원본 수치가 셀에 없으면 재구성하지 말고 그 사실을 보고한다.
- raw/ 계약(append-only·파일명 정규화)은 `docs/raw-layout.md`가 정본이다. 원본 xlsx는
  한 번 `raw/`에 들어가면 수정·삭제·rename할 수 없다 — 게이트 1을 통과시키기 전에
  개인정보를 확인해야 하는 이유다.
